# AGENTS.md

Guidance for AI agents working in this repository.

## What this project is

`podman-pi-agent` is a container image project, not an application. It builds a minimal Ubuntu 26.04 image that runs the **pi coding agent** (`@earendil-works/pi-coding-agent`) and **pi-web** (`@jmfederico/pi-web`) with full `systemd` as the entrypoint. It is designed to run as a podman container, a Proxmox LXC container, or via podman quadlets.

## Repository layout

| Path | Purpose |
|---|---|
| `Dockerfile` | Image definition (Ubuntu 26.04, systemd entrypoint, Node/Rust toolchains, pi + pi-web via npm) |
| `build.sh` | Resolves latest component versions, writes version `.txt` files, builds `pi-agent:latest` + a versioned tag |
| `build_and_run.sh` | `build.sh` + `run_local.sh` |
| `run.sh` | Example run script (creates container, sets root password at runtime, copies SSH key, attaches) |
| `run_local.sh` | Runs `run.sh` against the locally built `pi-agent:latest` image |
| `systemd/*.service` | `pi-web.service`, `pi-web-sessiond.service`, `pi-home-init.service` (seed an empty `/home/ubuntu` mount from `/opt/ubuntu_skeleton`) |
| `etc/pi-web/config.js` | pi-web gateway config, copied to `/etc/pi-web/config.js` |
| `bin/init-ubuntu.sh` | One-shot home-seeding script run by `pi-home-init.service` |
| `node_version.txt`, `pi_version.txt`, `pi_web_version.txt`, `rust_version.txt`, `pi_agent_tag.txt` | Generated by `build.sh` (gitignored); the tag file is used by CI to detect build skips |
| `.github/workflows/docker-image.yml` | GitHub Actions workflow (see below) |

## GitHub Actions workflow

`.github/workflows/docker-image.yml` builds and pushes the image to `ghcr.io` on:
- push to `master`
- daily cron (06:00 UTC)
- manual dispatch (with optional `force` input)

It runs `CT_TOOL=docker ./build.sh --build-ghcr` (adding `--force` when dispatched with force). `--build-ghcr` skips the build entirely if the resolved version tag already exists on ghcr.io, and signals the skip by **deleting `pi_agent_tag.txt`**; the login/push steps then silently skip. Never re-push a same-tag image with different content — that's the invariant this check protects.

## Building

```bash
./build.sh            # podman if available, else docker; CT_TOOL env var overrides
./build_and_run.sh    # build + local run
```

`build.sh` fetches the latest stable Node major, pi, pi-web, and Rust versions from their upstreams, writes them to the version `.txt` files, and builds with those as build args. Image tag format: `node-<major>-pi-<ver>-pi-web-<ver>-rust-<ver>`.

**Podman is available on this machine** and is the preferred tool for building and running locally.

## Running and testing

- `./run.sh` is an example, not a requirement — the container is just a systemd-based Ubuntu box.
- Persistence: bind-mount your state at `/home/ubuntu` (e.g. `-v ./home-data:/home/ubuntu`). If the mount is empty, `pi-home-init.service` seeds it with a home skeleton; put your own `~/.pi/agent/models.json` and other pi configs in the mounted volume.
- Ports: pi-web UI on `8504`, SSH (for root admin access) on `2223`.

### Testing with your own scripts

The container's default entrypoint is **full systemd** (`/sbin/init`). To test by bind-mounting your own scripts, you must **override the entrypoint**, e.g.:

```bash
podman run --rm -it \
  --entrypoint /bin/bash \
  -v ./my-script.sh:/tmp/my-script.sh \
  pi-agent:latest \
  /tmp/my-script.sh
```

With the default entrypoint you get a booted systemd system (log in as root if a password was set); with an overridden entrypoint systemd does not run, which is fine for quick script/container testing.

## Conventions

- **Always confirm with the user before committing to git or pushing.** Never commit/push without explicit user approval.
- **After completing a task, update `README.md` and `AGENTS.md`** to reflect any changes (new scripts, options, ports, behaviors).
- The root password is intentionally not baked into the image; `run.sh` sets it at runtime. Without it, there is no way in — that is the intended secure default.
- No automatic apt updates inside the image (update timers removed); update by rebuilding.
- `home-data/` and the version `.txt` files are gitignored (see `.gitignore`). `push.sh` is also intentionally ignored: it is a local helper script (run on another machine to push to a local repo) that must never be committed.
